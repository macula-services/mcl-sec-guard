# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and

## [Unreleased]

- **mcl_om floor 0.37.3**: stats carry hex-encoded caller ids (wire-clean; the
  previous images returned unknown_error from get_limits).

### Added

- **The admin console (P0, read-only).** `mcl_sec_guard_admin` listens on
  `MCL_SEC_GUARD_ADMIN_PORT` (default 8458, binds 0.0.0.0, no auth — the
  dev-fleet posture): `/` renders the proposal log as an auto-refreshing page
  for human review, `/proposals.ndjson` serves it raw. P1 adds approve/reject,
  which turns a reviewed proposal into a real `set_limits` call BY the guardian.
- The scaffold, generated by `rebar3 new mcl_service`: an OTP release that
  boots on `mcl_om`, joins the mesh, and answers `/health` on 8457.
- `mcl_sec_guard_service`, the six-callback `mcl_om_service` contract, announcing
  no capability and requesting no authority because it can do nothing yet.
- Unit tests asserting the contract's shape, including that the mesh-facing name
  and the reported version match the application's own.
- `Containerfile` building the release in a digest-pinned builder image and
  running it on the matching digest-pinned runtime image.
- `deploy/docker-compose.yml`, the service's own run contract.
- CI: `lint-and-test` (lint, eunit, dialyzer) on every push to `main` and
  every pull request. `build-and-push` to the registry: a push to `main`
  publishes `:latest`, and a `v*` tag publishes its own version and nothing
  else.
